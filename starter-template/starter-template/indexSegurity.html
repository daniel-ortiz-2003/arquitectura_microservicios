Arquitectura de Microservicios


Un microservicio es una forma de diseñar aplicaciones como una colección de pequeños servicios independientes, cada uno responsable de una única funcionalidad o parte del negocio, como por ejemplo. En una tienda online:
  • Un microservicio maneja los usuarios (registro, login).
  • Otro se encarga de los productos (listado, inventario).
  • Otro gestiona los pedidos.
  • Otro procesa los pagos.
  • Y otro envía notificaciones por correo o SMS.
Cada uno puede desarrollarse, desplegarse y escalar de forma independiente.

🔐 Detalles de la Arquitectura de Microservicios


🔑 Caracteristicas principales
1. Descomposición por dominio (DDD - Domain-Driven Design) Se divide la aplicación según las áreas de negocio.
Por ejemplo, en una tienda online:
Dominio de usuarios
Dominio de productos
Dominio de pedidos
Esto ayuda a organizar mejor el código y responsabilidades.
2. Despliegue independiente
Cada microservicio puede actualizarse sin afectar al resto del sistema. Esto permite hacer cambios rápidos y seguros.

Abrir/Cerrar
  • 3. Escalabilidad específica por servicio
    Si el microservicio de pagos recibe muchas solicitudes, puedes escalar solo ese servicio, sin necesidad de aumentar recursos para toda la aplicación.
    4. Uso de diferentes tecnologías
    No todos los microservicios tienen que estar hechos con la misma tecnología. Uno puede usar Node.js, otro Python, otro Java, etc., dependiendo de lo que sea más conveniente.
    5. Alta disponibilidad y resiliencia
    Como los servicios están separados, si uno falla, no necesariamente cae toda la aplicación. Además, se pueden diseñar sistemas redundantes para evitar caídas.

    ⚙️ Componentes esenciales
    Los microservicios deben comunicarse entre sí para funcionar como un todo cohesivo. Hay dos formas principales:

    Abrir/Cerrar
  • 1. Comunicación sincrónica (REST, gRPC)
    Un servicio llama directamente a otro y espera una respuesta.
    ✅ Rápida y simple.
    ❌ Puede generar acoplamiento (si un servicio falla, el otro también se ve afectado).
    📌 Ejemplo:
    El microservicio de "pedidos" llama al microservicio de "inventario" para verificar si hay stock antes de aceptar un pedido.

    Abrir/Cerrar
  • 2. Comunicación asincrónica (mensajería)
    Se usan colas o buses de eventos (como Kafka, RabbitMQ, AWS SQS). Los servicios no hablan directamente, sino que publican mensajes que otros consumen cuando puedan.
    ✅ Menos acoplamiento, mayor resiliencia.
    ❌ Más complejo de implementar.
    📌 Ejemplo:
    Cuando un usuario hace un pedido, se publica un evento "pedido_creado".
    El microservicio de notificaciones lo recibe y manda un email automáticamente

    ✅❌ Ventajas y desventajas de microservicios
    ✅ Ventajas:
    Modularidad : La aplicación está dividida en partes pequeñas y manejables.
    Escalabilidad : Puedes escalar solo los servicios que necesitan más recursos.
    Flexibilidad tecnológica : Cada servicio puede usar la tecnología más adecuada.
    Equipos pequeños e independientes : Equipos pequeños pueden trabajar en paralelo en distintos servicios.
    Mayor disponibilidad : Si un servicio falla, no se cae toda la aplicación.

    Abrir/Cerrar
  • ❌ Desventajas:
    Complejidad operativa : Gestionar múltiples servicios requiere herramientas como Docker, Kubernetes, etc.
    Gestión de datos más compleja : Cada servicio tiene su propia base de datos, lo que complica transacciones ACID entre servicios.
    Más difícil de probar y depurar : Con tantos componentes interconectados, localizar errores puede ser complicado.
    Costos iniciales altos : Requiere infraestructura más robusta desde el principio.

    Recursos prácticos

    📌 Conclusiones

    La arquitectura de microservicios permite construir sistemas grandes de forma modular, flexible y escalable. Es ideal para empresas que tienen equipos distribuidos y necesitan evolucionar rápido.
